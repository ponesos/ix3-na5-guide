# 로드맵

최종 수정: 2026-09-08

처음부터 자체 웹 서버를 두지 않는 선택은 **유지한다.** 공유 방식이 공개 URL이므로 **GitHub Pages 정적 사이트**가 1단계에 맞다. 오너가 당장 필요한 것은 실시간 API가 아니라 **날짜가 찍힌 사실**(트림, 부품번호, 시승기 링크)이다.

## 서버로 넘어가는 트리거

아래 중 **둘 이상**이 반복되면 `docs/ARCHITECTURE.md`의 서버 전환을 착수한다.

- 가격·환율·재고를 자동으로 자주 갱신해야 한다
- 댓글·로그인·푸시·개인화가 필요하다
- 검색·앱 클라이언트가 API를 요구한다
- Pages 배포만으로는 갱신 주기·권한 관리가 안 된다

그때도 **JSON 스키마는 유지**하고, UI는 같은 필드를 API에서 읽도록 바꾼다.

## Phase 0 — 지금 (문서 + 골격)

- 제품·요구·아키텍처·데이터·법률 문서
- `data/` JSON과 `schemas/`
- `site/` 홈, 액세서리, 비교/시승기 자리표시
- 독일 NA5 전용 액세서리 샘플로 스키마 검증

## Phase 1 — 액세서리 카탈로그

- DE 공식몰 NA5 전용 항목 전수(사람이 출처를 보고 JSON에 기록)
- UK 공식몰에 동일 부품이 있으면 `markets` 배열에 추가
- 검색(부품번호·한글명), 필터 고도화
- 수집 체크리스트: 제목, 품번, 가격, 날짜, URL, 옵션 코드(SA), VIN 주의

## Phase 2 — 구매 검토

- 국내 제원 보강 (휠, 색상, 옵션 패키지)
- 동급 비교 표
- 시승기 카드 (유튜브·기사, 공정 요약)

## Phase 3 — 오너 운영

- 초기 설정, 충전(800V·완속), My BMW, 알려진 이슈
- 제보: Issue 템플릿 또는 mailto
- 피드백 반영 주기 (주 1회 등)를 이 문서에 적는다

## Phase 4 — 플랫폼

- 간단 서버 또는 Pages + 서버리스
- `vehicleId`만 바꿔 차종 추가
- 앱·수익(제휴·구독)은 [LEGAL.md](LEGAL.md) 검토 후

## 작업 순서 (항상)

1. `docs/` 해당 파일 수정  
2. `schemas/` 필요 시 수정  
3. `data/` 수정 후 `scripts/sync-data.sh`  
4. `site/` UI  
5. 브라우저에서 확인
